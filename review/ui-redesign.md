# 问题组页面 UI 改进

> Historical engineering review; findings describe the version reviewed at that time.
> Current implementation: [Architecture](../docs/architecture.md) and [Progress](../docs/progress.md).
>
> 历史工程评审，结论对应当时受评版本。当前实现见[系统架构](../docs/architecture.md)和[项目进度](../docs/progress.md)。

## 任务与约束

用户要求：

1. 前端界面增加顺滑的动画；
2. 问题组页重新布局：顶部筛选栏 + 搜索栏，下方问题组卡片；
3. 用不同颜色标识问题组状态；
4. 用合适字号强调问题组具体内容；
5. 卡片可点击进入问题组详情页，查看相关评论与详细信息。

约束：沿用现有 ReviewLens 视觉语言（深蓝侧栏、浅色卡片、中文界面），前端仍是纯静态 mock，
不接真实接口、不引入构建工具或外部依赖。

## 方向与关键决定

- **状态只由卡片底色 + 状态徽标承担**，不把状态色铺到统计数字、分类标签和链接上；
  分类改为中性 chip，优先级用独立的高/中/低标签在标题上方表达。
- 统计数字用中性深蓝并放大，让「AI 建议 / 人工确认 / 相关评论」成为可扫视的数据锚点。
- 详情页以「问题组 → 相关评论 → 判断依据 → 处理记录」为信息顺序，避免同一句话在多个面板重复。
- 动效只服务三件事：主操作反馈、状态切换来路、首次进入出场；高频筛选与搜索不做长动画。

## 改动清单

### 问题组列表 `frontend/app.js` / `frontend/styles.css`

- 顶部工具栏：搜索框（标题/类别/商品/描述/证据全文）、状态分段筛选（带数量与滑动指示器）、
  类别/商品下拉、结果计数（`共 8 组 · 匹配 3`）、清除筛选。
- 桌面为三列卡片；1240px 两列；860px 以下单列。
- 卡片：状态底色 + 状态徽标（待确认/已确认/已解决/已忽略），中性分类 chip，
  高/中/低优先级标签，19px 标题，两行摘要，证据引用，三个统计数字和「查看详情 →」。
- 卡片整体是 `<a href="#/issues/{id}">`，支持键盘、右键新标签打开与浏览器前进/后退；
  从详情返回列表时恢复原滚动位置、保留筛选与搜索状态。
- 搜索命中词在标题、摘要、证据中高亮；无结果时给出可恢复的空状态。
- 移动端：搜索 + 「筛选」按钮一行；类别/商品默认折叠；状态筛选一行横向滚动；
  结果计数在筛选行下方；首张卡片在 390×844 下约 y=440 出现（此前筛选面板占约 305px）。

### 问题组详情 `frontend/app.js`

新路由 `#/issues/{id}`（未知 id 显示空状态）：

- 顶部标题不再重复问题组名，仅保留 breadcrumb 式的「← 返回问题组」（放在卡片内部，避免孤立空带）。
- 状态色 hero：状态徽标、分类 chip、优先级、标题、商品、摘要、证据引用、更新时间、来源批次；
  右侧三个统计与确认/跟进/驳回按钮（已确认后确认按钮禁用）。
- 「判断依据」：建议跟进、类别/商品、来源批次、最近更新、关闭说明；AI 建议关联只展示
  评论 ID + 置信度 + 「证据见相关评论」，不再重复整段原文；「处理记录」用时间线展示
  AI 提取与当前状态。
- 「相关评论」：评论 ID、评分、平台/店铺、日期、原文（证据高亮）、类别与 has_issue 徽标。
- 状态动作只更新内存 mock，并立即重渲染状态色、徽标、处理记录和按钮禁用态。

### 动效

- 页面进入：`page-enter` 360ms（`cubic-bezier(.22,1,.36,1)`），淡入 + 上移 10px。
- 卡片首次进入：`issue-card-enter` 440ms，按 `--i` 每张延迟 55ms，总时长不超过 600ms。
- 筛选/搜索刷新：`issue-card-fade` 180ms，不重播整页出场。
- 状态分段选中：白色指示器用 transform/width 260ms 滑动到新选项（桌面）；移动端改为
  横向滚动 + 选中 pill 背景。
- 悬停：卡片上浮 3px、阴影加深、箭头右移；按下 `scale(.98)`；相关评论行有轻微抬升。
- 详情进入、评论逐条入场；`prefers-reduced-motion: reduce` 下关闭位移/延迟，直接到位。
- 返回列表时恢复滚动位置（`state.issueScroll`）。

## 自查与评审

- 独立视觉评审（子 Agent，按 oil-ui reviewer-manual，仅看截图）：**7/10**。
  主要 P1：状态色用途过散、详情页一句话重复、移动端首屏被筛选面板占满、详情标题重复；
  P2：搜索命中不可见、已确认 tab 数量、关联/相关评论命名不一致、mock 字样露出。
- 本轮已修正：状态色收敛为底色 + 徽标；统计/分类/链接中性化；优先级独立标签；
  详情去掉重复标题与建议原文，新增处理记录时间线；移动端折叠筛选、状态横向滚动；
  搜索高亮 + `共 N 组 · 匹配 M`；统一「相关评论」；移除顶栏 Mock chip 与侧栏 mock 文案；
  确认后禁用确认按钮；评论在移动端排到判断依据之前。
- 未改：详情页移动端的按钮仍为纵向排列（未做 sticky bottom bar）；状态筛选在 390px 下
  仍可能横向滚动。
- 截图工具 lint：仅剩「标题上方的眉标」1 类，属既有全局 masthead（`#page-kicker`），
  本次未改全局品牌壳；对比度/嵌套卡片问题均已清零。其他页面（批次/复核）仍有既有
  对比度与 12px 正文提示，不在本次问题组改版范围。
- 动效录屏：`shoot.mjs --record/--evidence` 在本机报 `__oilMotion is not defined`，
  未能产出视频证据；动效以代码审查 + 交互截图（筛选/搜索/详情/动作）核对，未独立录制。

## 证据

验收时使用 headless Chrome 检查了桌面 1440×1000、移动 390×844、200% 缩放、
筛选/搜索/已忽略状态与详情跳转；截图与中间产物已在整理中删除，只保留本说明。
如需复现：本地起静态服务后打开 `frontend/index.html`，或运行
`docker compose up --build` 后访问 `/ui/`。

## 已知限制

- 前端仍为 mock 数据；详情里的评论、批次、置信度均来自 `frontend/mock-data.js`。
- 没有接入 `/issues/{id}/actions` 等真实接口；动作只在当前页面状态内生效。
- 移动端只验证了 390×844 与 768×1024；未覆盖真机触摸滚动惯性。
